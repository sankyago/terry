# Cruise — практика водіння у 3D

Інтерактивний веб-тренажер для відпрацювання навичок водіння. Перша версія містить одну завершену вправу —
**«Зупинка в позначеній зоні»**: рушити зі старту, проїхати коротку дорогу з поворотом праворуч, плавно
зупинитися всім корпусом у зоні, простояти щонайменше 2 секунди й перевести селектор у **P**.

> Це авторська навчальна вправа. Її оцінювання **не є** офіційними критеріями практичного іспиту.

## Запуск

Потрібен Node.js 20+ (перевірено на 22).

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # unit-тести (Vitest)
npm run typecheck  # перевірка типів
npm run build      # продакшн-збірка в dist/
npm run preview    # перегляд зібраної версії
```

Щоб відкрити з телефона в тій самій мережі: `npm run dev -- --host` і перейти за IP-адресою комп'ютера.

Збірка використовує відносний `base: './'`, тож `dist/` можна викласти на будь-який статичний хостинг.

### GitHub Pages

`npm run deploy:pages` проганяє тести, збирає застосунок і публікує `dist/` у гілку `gh-pages`.
У налаштуваннях репозиторію: **Settings → Pages → Build and deployment → Deploy from a branch → `gh-pages` / `(root)`**.

Для автоматичного деплою при кожному пуші в `main` скопіюйте `scripts/github-pages-workflow.yml` у
`.github/workflows/pages.yml` і оберіть у Settings → Pages джерело **GitHub Actions**.

## Режими

- **Навчання** — покрокові підказки (5 кроків), пояснення кожної помилки одразу, підсвічування зони, коли
  корпус повністю в ній. Передчасне P не завершує спробу, а пояснює, що виправити.
- **Перевірка** — без підказок; перемикання в P після старту завершує спробу, результат — у кінці.

## Керування

**Комп'ютер**

| Дія | Клавіші |
| --- | --- |
| Газ / гальмо | `W` / `S` або `↑` / `↓` (плавна рампа) |
| Повне гальмо | `Пробіл` |
| Кермо | `A` / `D` або `←` / `→` |
| Селектор P / R / N / D | `1`–`4`, також `P`, `R`, `N`; `Z` / `X` — крок вгору / вниз |
| Поворотники | `Q` (лівий) / `E` (правий) |
| Камера | `C` |
| Пауза | `Esc` |

**Телефон** (горизонтально): кермо ліворуч (обертайте пальцем), педалі праворуч (вище на педалі — сильніше),
селектор поряд із педалями, поворотники — стрілки біля спідометра. Кермо й педаль працюють одночасно
(Pointer Events + pointer capture).

Як у реальному автоматі: вивести селектор із P можна лише з натиснутим гальмом, P та D↔R — тільки коли авто
практично стоїть; у D/R без педалей авто повільно «повзе», тож для зупинки тримайте гальмо.

## Що перевіряється

| Подія | Правило |
| --- | --- |
| Перевищення швидкості | > 20 км/год; нова подія лише після спаду нижче 18 км/год на ≥1 с |
| Зіткнення | окремо для кожної перешкоди; повтор лише після ≥0,6 с без контакту. Зіткнення = вправу не виконано |
| Виїзд за межі дороги | будь-який кут корпусу за краєм; повтор після ≥1 с на дорозі |
| Поворот без покажчика | один раз на вході в поворот, якщо не увімкнено правий покажчик |
| Фінальна зупинка | усі 4 кути корпусу в зоні, швидкість < 0,5 км/год безперервно ≥ 2 с, потім P |

Стани вправи: `waiting` (очікування старту) → `driving` (рух) ⇄ `stopping` (зупинка в зоні) → `finished`.
Результат: «Вправу виконано», «Виконано із зауваженнями» (є некритичні помилки) або «Вправу не виконано».

## Структура

```
src/
  config.ts            константи авто, вправи, кроку симуляції
  sim/                 чиста симуляція без Babylon/DOM
    vehicle.ts         кінематична модель «велосипед», селектор, гальмо, повзучість
    collision.ts       OBB/коло, SAT
    world.ts           розв'язання зіткнень, положення авто відносно дороги та зони
    track.ts           осьова лінія дороги, зона, перешкоди (єдине джерело для фізики і графіки)
    indicators.ts      поворотники з автовимкненням
  exercise/            машина станів вправи, тригери помилок, підказки, тексти
  input/InputManager.ts клавіатура + екранні команди → DriveCommand
  scene/               процедурна low-poly сцена й модель авто, рівні якості
  camera/CameraRig.ts  камера ззаду зі згладжуванням, вид водія, обліт меню
  game/Game.ts         рушій, фіксований крок 60 Гц з інтерполяцією, пауза, події для UI
  audio/AudioEngine.ts синтезований звук (WebAudio), без файлів
  storage/storage.ts   налаштування та прогрес у localStorage
  ui/                  React: старт, HUD, сенсорне керування, пауза, результати
tests/                 Vitest: умови завершення, захист від повторів, фізика, сховище
```

Продуктивність: симуляція йде з фіксованим кроком 1/60 с незалежно від FPS; React отримує знімок HUD не частіше
10 разів на секунду; статичні меші зливаються за матеріалами (кілька draw call); pixel ratio обмежується
(1,25 — «Економна», 2 — «Висока»; на сенсорних пристроях за замовчуванням економна, без тіней і MSAA).
У паузі можна увімкнути лічильник FPS.

Параметр `?debug` в адресі відкриває об'єкт гри як `window.__cruise` — для автоматичних перевірок.

## Відомі обмеження

- Ціль — стабільні 30 FPS на середньому телефоні, але **на реальних пристроях це ще не виміряно**.
- Фізика спрощена (кінематична модель без заносу та підвіски); бордюри низькі й не є перешкодою —
  їх перетин рахується як виїзд за дорогу.
- Конуси нерухомі; зіткнення гасить швидкість і виштовхує авто.
- Пакет Babylon.js займає ≈400 КБ gzip; перше завантаження на повільній мережі може тривати кілька секунд.
- Екран не блокує орієнтацію і не вмикає повноекранний режим — у портреті лише показується порада.
- Одна вправа, один автомобіль, без звуку оточення.
